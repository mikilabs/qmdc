# QMD-73: `.qmdcignore` does not work like `.gitignore` in any parser

## `.qmdcignore` lines mean three different things [[qmd73_qmdcignore: Bug]]

The spec says `.qmdcignore` "works like .gitignore" (`docs/architecture/algorithms.qmd.md`). None of
the three parsers does. Each one hands a line to a different glob engine (Rust `globset`, Python
`fnmatch`, TypeScript `minimatch`), and each engine gives `*`, `/` and `!` its own meaning, so one
ignore file hides different files in each parser.

Found in QMD-72: `workspace validate .` at this repository's root reports 292 errors in TypeScript,
2 in Rust and 0 in Python. 286 of the TypeScript errors come from files under `tests/`: the root line
`tests/*` hides that whole tree in Rust and Python, and only its first level in TypeScript.

### Goals [[goals: [Goal]]]

#### A1: Decide ignored or kept exactly as git does [[qmd73_goal_a1]]

For every line form in the triage matrix, all three parsers keep and hide the same files as
`git ls-files --others --exclude-standard` does with the same lines installed as `.gitignore`. A star
or a question mark never matches a slash. A line that matches a directory hides everything under it.
A line with no slash, or only a trailing one, matches at any depth. A leading or middle slash anchors
the line to the directory of the ignore file. A trailing slash matches directories only. A negated
line re-includes a path, except below an excluded directory. Blank lines, comments and trailing
spaces are dropped. Matching is case-sensitive on every OS.

- group: A_semantics
- done: true

#### A2: One ignore decision per parser, used by every scan [[qmd73_goal_a2]]

The file scan, workspace discovery, the bounded `--with` scan and the Rust LSP folder scan all ask
one function, and that function checks a path's ancestor directories before the path itself. The
per-call-site workarounds go away, including Python's probe of a made-up `__dummy__` file to decide
whether a directory is ignored.

- group: A_semantics
- done: true

#### B1: The five regression fixtures pass [[qmd73_goal_b1]]

The five fixtures under `tests/workspace/qmdcignore-gitignore/` pass in all three parsers. Their
expected file lists are git's answers, generated by `artifacts/gen_fixtures.py`, not typed by hand.

- group: B_tests
- done: true

#### B2: Pin the re-include rule before negation works [[qmd73_goal_b2]]

Add `06-no-re-include-under-excluded-directory`: `keep/` followed by `!keep/important.qmd.md`, where
git hides both files. It passes today in Rust and Python only because both ignore the negated line,
so it is not a regression test yet. It becomes the guard as soon as negation works, and the triage
measured a library that gets exactly this wrong.

- group: B_tests
- done: true

#### B3: Run the whole matrix against each parser's matcher [[qmd73_goal_b3]]

The 38 line forms in `artifacts/gitignore-matrix.json`, with git's answers, move to `tests/` and are
read by a small data-driven test in each language that calls the ignore function directly. Five
workspace fixtures pin the reported shapes; the matrix pins the semantics, so a fix cannot pass by
matching only those five.

- group: B_tests
- done: true

#### C1: The repository root scans the same files in all three [[qmd73_goal_c1]]

`workspace validate .` at the repository root scans the same 115 files in every parser, and the
TypeScript errors that came from `tests/` go away. The 2 Rust errors that remain have a different
cause, recorded in the findings and not fixed here.

- group: C_repo
- done: true

#### D1: Write the rules into the spec [[qmd73_goal_d1]]

Replace "works like .gitignore" in `docs/architecture/algorithms.qmd.md` with the rules from A1, and
state which ignore file governs what, as it behaves today in all three: each workspace reads the
`.qmdcignore` in its own root, a container's file governs workspace discovery only, and a
`.qmdcignore` in a subdirectory is not read.

- group: D_docs
- done: true

#### D2: Tell users which lines change meaning [[qmd73_goal_d2]]

Add a `CHANGELOG.md` entry under Unreleased naming, per parser, the line forms that hide more or fewer
files after the fix. For example, `docs/*.qmd.md` stops hiding `docs/sub/` in Rust and Python, and
`generated` starts hiding a directory in all three.

- group: D_docs
- done: true
